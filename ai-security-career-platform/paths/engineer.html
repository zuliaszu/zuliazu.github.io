AI Security Engineer

Builds and secures LLM and agent applications, adding guardrails and secure architecture on top of existing software engineering skills.

Start with the skills Take the diagnostic first
Evidence16 of 48 research postings selected for this path. Mostly US-based (11 of 16 postings) with single postings each in the UK, Switzerland, Canada/US, Australia and remote US, and skewed senior: 7 Senior, 2 Staff, 2 Senior Staff, 1 Principal, against 3 mid-level roles (n=16 postings).
Pay, as postedListed ranges include 152300-246400 USD, 320000-485000 USD, and 154000-220000 USD, though roughly half of the 16 postings gave no figure at all.
Titles you will seeSenior Software Engineer, AI Security, Agentic AI Security Engineer, Staff Security Software Engineer, Agentic Security Engineering, Principal Agentic AI Security Engineer, Security Engineer, AI, AI Engineer (CISO GenAI portfolio)

What you do

  • Write code that uses or wraps LLMs and agents, then find and close the ways it can be misused (LLM 94%, Agents 81%, n=16 postings).
  • Review and harden agentic systems that call tools, APIs, or the MCP protocol, since over a third of postings name MCP or RAG directly (MCP 38%, RAG 38%, n=16).
  • Apply application security practice, secure SDLC, code review, vulnerability management, to AI-specific code paths, not just classic web apps (AppSec 31%, n=16).
  • Secure the cloud infrastructure the models and agents run on (Cloud 69%, n=16).
  • Design or review architecture for AI features so security is built in rather than bolted on afterwards (Architecture 62%, n=16).

Prove it: Build a small RAG or agent app, then add and test guardrails

Allow about 10 hours, plus setup. This is a practice task, not a certification or proof of job readiness. Use fictional data and systems you own or have written permission to test. Optional cloud services or licensed standards may cost money.

Build a small retrieval or agent application, break it with known attack payloads, then add input and output guardrails and show they work. Postings in this cluster ask for demonstrated ability to secure AI code; a before-and-after repo is that demonstration. Run every attack only against the app you built on your own machine. The same payloads pointed at a hosted service or an employer's system need written authorisation first.

  1. Install Python and a free local or API-based LLM (for example a small open model or a free-tier API key). The exercise assumes you can already write and run Python; if not, work the Coding skill page first.
  2. Build a small RAG app (load 5 to 10 text documents, embed them, answer questions from the retrieved context) or a small agent that calls 1 to 2 tools. If you would rather not start from zero, run Damn Vulnerable LLM Agent locally and treat it as your unprotected app.
  3. Write down 8 to 10 ways to make it misbehave: prompt injection in a document, jailbreak in user input, tool-calling abuse, data exfiltration attempts.
  4. Run each attack against the unprotected app and record what happens (pass or fail).
  5. Add input and output guardrails: input filtering, output validation, a system prompt hardened against injection, or an allowlist for tool calls.
  6. Re-run the same attacks against the guarded version and record the new results.
  7. Read the OWASP Top 10 for LLM Applications and map each of your test attacks to the OWASP category it belongs to.
  8. Write up the before/after results as a short report with code.

Deliverable: A short repo containing the app, the attack list, before/after test results, and a written mapping to OWASP LLM Top 10 categories, something you can walk an interviewer through.

Self-check

  • The app actually runs end to end without manual fixes during a demo.
  • At least 8 distinct attacks were tried against the unprotected version.
  • At least 3 of those attacks were blocked or changed behaviour after guardrails were added.
  • Every attack in the list is mapped to an OWASP LLM Top 10 category.
  • The write-up states clearly which attacks still succeed after guardrails, not just the ones that were fixed.
